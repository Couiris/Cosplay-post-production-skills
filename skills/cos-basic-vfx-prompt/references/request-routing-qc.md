# 请求路由、执行策略与质量门

本文件把用户自然语言编译成最少够用的模块集合，并在生成 JSON 前阻止误路由、过度修改和不可执行承诺。

## 1. 先生成 intent_card

```json
{
  "requested_changes": ["用户明确要求的改动"],
  "explicit_preserves": ["用户明确要求保留的内容"],
  "forbidden_changes": ["用户明确禁止的改动"],
  "reference_roles": ["每张参考图只提供什么"],
  "deliverable": "聊天内 JSON | 保存为文件 | 仅方案",
  "uncertainties": ["执行时检测或需要用户选择的事项"]
}
```

- 用户指令优先于 skill 默认值；默认值只补充不会改变核心结果的空白。
- 没有图时不假造坐标、光位、人数、服装材质或角色设定，写“执行时检测”。
- 只有缺失选择会显著改变人物、构图、版权边界或交付格式时才询问；其他信息用保守假设并写入 `uncertainties`。

## 2. 常见意图路由

| 用户意图 | 主模块 | 常见依赖或后续 |
|---|---|---|
| 清路人、器材、杂物 | `cleanup_plan` | `capture_match_plan` 仅在补洞成像不一致时启用 |
| 暗光、高 ISO 彩噪、条带、夜景压缩 | `low_light_rescue` | 默认已包含降噪与轻度细节恢复；除非用户另要超分或普通失焦修复，不叠加 `enhance_plan` |
| 普通失焦、运动模糊、明确超分 | `enhance_plan` | 发现摩尔纹/色边/压缩块时才先用 `capture_artifact_fix` |
| 皮肤、假发、服装、道具更有质感 | `material_texture_enhance_plan` | 不自动启用瘦脸、液化或全局调色 |
| 抠图亮边、绿边、紫边、边缘脏 | `edge_halo_spill_fix` | 先确认不是角色设计本身的描边/反光 |
| 加实体道具、耳尾、分身、悬浮 | 对应增材模块 | `shadow_plan` → `subject_harmonize_plan` → `capture_match_plan` |
| 加法阵、火焰、雷电、翅膀、天气 | `vfx_plan` | 自发光补 `vfx_relight_mask`；多效果共享运动、配色和时间相位 |
| 加灯、改灯位、窗光、轮廓灯 | `virtual_lighting_plan` | 先冻结 `subject_light_profile`；不把全图染色当灯光 |
| 合并参考图的局部对象或光效 | `image_blend_plan` | 先验收；仅检测到对应问题时分别启用边缘修复、主体协调或成像匹配 |
| 统一新增内容的光色影 | `subject_harmonize_plan` | 只调整新增内容与窄接触区，底图是基准 |
| 统一噪点、锐度、色边、压缩和镜头痕迹 | `capture_match_plan` | 在几何、边缘、光影已经通过后执行 |
| 导出尺寸、色彩空间、位深和输出锐化 | `output_finish_plan` | 永远最后执行，不负责修复上游错误 |

不要因为用户说“高级、大片、电影感”就自动启用所有精修、VFX、虚化和海报模块。先把抽象词翻译成可观察的影调、材质、光比、景深或构图目标，再只选必要模块。

## 3. 基础后期与合成 skill 的边界

- 新增像素主要位于局部授权区，人物、机位和大部分背景保留：本 skill。
- 需要重铺较大地面/中景但保留场馆墙顶与机位：半合成。
- 供体图或新设定成为完整背景，需要重建世界、建筑、载具、巨物或人物位置：大合成。
- 仅需要无特效调色分析和常规精修参数，不需要插件 JSON：`cosplay-clean-retouch`。

## 4. 模块依赖与顺序

按实际启用项从左到右执行：

`技术修复 → 人物/服装结构 → 溶图与增材 → 影子与主体协调 → 虚拟灯/VFX → 全局调色与景深 → 成像特征匹配 → 输出收尾`

- 结构未通过前不做材质锐化；否则会把错误几何固化得更明显。
- 溶图/新增后先验收边缘：只有出现无来源白边、绿边、双边或供体色溢才插入 `edge_halo_spill_fix`；真实轮廓光、霓虹辉光和透明材质过渡必须保留。
- 光位未通过前不加 bloom、颗粒或胶片包装；后期质感不能修正矛盾投影。
- `output_finish_plan` 只负责交付规格和克制的输出锐化，不得重新生成细节。

### 4.1 重叠意图排他判定

- **已有光影再分配**：`lighting_reshape`；不新增可定位灯源。
- **新增窗光、摄影灯、霓虹灯或投影灯**：`virtual_lighting_plan`；每盏灯独立写光路。
- **法阵、火焰、雷电等自发光特效的局部反射**：放在该 effect 的 `vfx_relight_mask`，不另开虚拟灯。
- 特效库中的轮廓光/霓虹补光只有在用户明确要“VFX 光效外观”时使用；普通补光请求不从效果库选效。
- `low_light_rescue` 负责暗光场景的技术降噪与可见细节恢复；不要再让 `enhance_plan` 重复降噪。
- `hair_fix` 只修断层、发缝、异常毛流等结构；仅提升假发丝缎感、粗糙度与细节时使用 `material_texture_enhance_plan`。

## 5. 三种执行策略

- `single_pass`：低风险、少模块、无共享锁定维度冲突。
- `ordered_micro_passes`：复杂请求仍由一个预设承载，执行器按 `pass_plan` 顺序处理。
- `checkpointed_multi_turn`：仅在执行器明确支持连续编辑时使用。每一轮都有输入检查点、授权区、通过条件和失败回滚点；当前轮未通过不得继续。

`checkpointed_multi_turn` 的 pass 额外写：

```json
{
  "checkpoint_required": true,
  "continue_only_if": ["本轮必须通过的条件"],
  "rollback_to": "previous_accepted_output"
}
```

## 6. 五道质量门

最终 `acceptance_tests` 至少覆盖这些可观察门槛：

1. **范围门**：所有可见改变都属于用户要求或必要的物理融入；授权区外无新内容。
2. **身份与几何门**：人数、脸、姿态、手势、坐标、画幅、机位和透视符合锁定合同。
3. **合成门**：尺度、遮挡、接触、投影、边缘、光色、景深和颗粒属于同一相机空间。
4. **伪影门**：无双边、鬼影、硬切、色溢、锐化白边、重复纹理、乱码和多余肢体。
5. **交付门**：JSON 合法、参数可解析、输出尺寸/色彩空间明确，失败项能映射到最小重试区。

质量门是通过/拒绝条件，不使用“高级感 90 分”这类不可观察评分。

## 7. 提示词压缩

- 共享锁定合同只写一次；模块 `preserve` 只引用与本模块最相关的 3–6 项。
- 同一事实只放在一个事实来源：模块键来自注册表，字段来自输出 schema，效果物理来自特效编译器。
- 删除不能改变生成决策的同义形容词；把“自然、真实、高级、电影感”改成可观察的空间、材质、光影和成像要求。
- 负面词只列本次最可能的失败，不重复已经由正向终态和验收充分表达的内容。
